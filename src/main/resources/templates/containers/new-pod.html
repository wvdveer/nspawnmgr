The command run as the pod's main process, like a Dockerfile CMD - left blank, the pod trusts whatever command the template's own image already has built in. If that's a plain interactive shell (or anything else that doesn't keep running on its own), the pod will exit within moments of starting - it won't fail to create, but it'll immediately show as stopped again. Editable later from the pod's own page, but only takes effect the next time it's recreated (the pod must be stopped first).

SSH, RDP, and VNC access aren't set up automatically for a pod - enable them from the pod's own page once it's running.
