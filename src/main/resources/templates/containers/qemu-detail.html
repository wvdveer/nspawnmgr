Manage

"Stop" asks the guest OS to shut down (an ACPI request) — it does nothing until an OS is actually installed. "Force stop" always works, no guest cooperation needed.

Create template from this machine

Copies this VM's current disk into a brand-new, independent template (visible on /admin/templates afterwards, and selectable from the New QEMU page's "From template" option) - only while this VM is STOPPED, since copying a live disk risks an inconsistent image as the guest writes to it.

Remote access

VNC connects to this VM's own hypervisor console — the same screen a physical monitor would show, working even before a guest OS is installed. It's configured automatically; there's nothing to enable. SSH and RDP connect to services running inside the guest OS instead — enable them once one is installed and running, same reachability check as any other container.

VNC: connected automatically.

SSH: not connected via nspawnmgr. SSH: connected (prompts for credentials).
RDP: not connected via nspawnmgr. RDP: connected (prompts for credentials).

Removable media

The VM's boot CD-ROM device. Swapping it here takes effect immediately if the VM is currently running (no restart needed) and also becomes the default for its next boot — the same "boot device" a physical machine's optical drive would be.
