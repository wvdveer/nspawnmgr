Listed live while the container is running; shows the last-known list otherwise. Adding a user or changing a password needs the container running — if it isn't (or no stored sudo secret is configured), the request waits for an admin to approve it.

SSH/RDP/VNC currently connect as admin. Use "Make primary" below to switch to any other account in this list — same approval rules as adding a user or changing a password.

    SSH credentials

    nspawnmgr has no stored SSH credential for this machine. If it's stuck in BOOTING, this is usually why — without one, nspawnmgr can't confirm SSH is reachable and it never flips to RUNNING. If this machine already has SSH access set up some other way, record its account name and private key here so nspawnmgr can use them.

    Remote access

    For a protocol nspawnmgr didn't set up itself (a discovered machine, or RDP declined when this container was created) — checks the port is actually listening before connecting it to Guacamole. You'll be prompted for credentials each time you connect, since nspawnmgr doesn't generate or store an account for it.

    SSH: not connected via nspawnmgr. SSH: connected (prompts for credentials).
    RDP: not connected via nspawnmgr. RDP: connected (prompts for credentials).
    VNC: not connected via nspawnmgr. VNC: connected (prompts for credentials).

    Guacamole's RDP negotiation mode. Leave on ANY unless RDP fails to connect — some xrdp versions (e.g. Fedora's) reject ANY for reasons unrelated to credentials; RDP (classic security) is the known workaround. Applies immediately if RDP is already connected, no restart needed.

    Local login (PAM)

    Replaces this container's own local password check for whichever services are ticked below, checking the source selected instead — useful when a container's local login is broken, or to reuse nspawnmgr's own login backend. Applies immediately if the container is running; otherwise takes effect the next time it starts. Choosing "nspawnmgr auth backend" lets any user who can authenticate against that backend log in as this container's account — this container's own owner/sharing list isn't consulted by this check.

    Package manager

    This machine has no template, so nspawnmgr doesn't otherwise know which package manager it uses. Set it here to enable package installation below.

    Install package

    Packages an admin has uploaded for this container's package manager (see the Packages admin page). For APT, a missing dependency is detected and fetched automatically before installing (it shows up in the Packages admin page afterward, same as any other auto-fetched package). Other package managers install the file directly — a missing dependency there shows up as a visible error below, it's not fixed automatically.
