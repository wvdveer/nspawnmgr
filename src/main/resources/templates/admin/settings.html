Guacamole

Must match whatever your guacamole-auth-jdbc extension calls itself in guacamole.properties (see the Guacamole section below) — shown in red if it doesn't currently match. "Refresh" copies the detected value across.

Host

The hostname/DNS name users outside this host should use — what goes in a browser's address bar, and what the "Refresh" buttons below fill into every Guacamole/Auth URL (alongside the protocol/port they already pull from Tomcat). Seeded to this machine's actual hostname on .deb installs; defaults to localhost otherwise.

Not the same as External hostname above — this is what Guacamole's guacd uses to reach a custom port mapping's host-forwarded port (ordinary SSH/RDP/VNC always dial a container's own internal address directly, bypassing this). 10.100.0.1 (nspawnbr0's own address) on a packaged install, since guacd runs inside nspawnmgr's own self-hosted machine and those forwards are bound on the bare host's network stack, not any particular container's.

Provisioning

SSH (sudo-capable local account)

Changing these is tested with a real SSH connection before being accepted — see docs/administrator-guide.md §3 "The sudo-capable SSH account".

Filesystem paths (nspawn)

Must match /etc/sudoers.d/nspawnmgr_exec's hardcoded paths, or every privileged operation (container start/stop, outbound access, Restart Tomcat below) will start failing — sudo fails safe by simply refusing the new path, it does not follow this setting.

DNS

Comma-separated IP addresses (e.g. a corporate DNS server) that managed containers' non-.internal lookups (apt/dnf/pacman mirrors, etc.) are forwarded to. Defaults to 1.1.1.1,9.9.9.9.

Auth (auth.war)

auth.war was detected at the configured login URL. These settings are mirrored to a shared file auth.war reads on every request — changes take effect immediately, no restart needed.

Guacamole (guacamole.properties)

Saving does not restart Tomcat. Guacamole will not see these changes until you run sudo systemctl restart tomcat9.
